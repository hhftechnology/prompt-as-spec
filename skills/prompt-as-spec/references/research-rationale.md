# Research Rationale

Use this summary when explaining why the three-layer specification structure is designed the way it is, or when calibrating how strict a prompt should be.

| Specification Element             | Empirical Finding                                                                                                                                      | Primary Source                                                                                   |
| :-------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------- |
| Negative constraints (Layer 1)    | Across 679 GitHub agent rule files (25,532 rules), every individually beneficial rule in controlled tests was a negative constraint ("do not X"), while distorting rules were positive directives ("do X"). | [Guardrails Beat Guidance (arXiv:2604.11088)](https://arxiv.org/html/2604.11088v2)               |
| Pinned stack & bans (Layer 2)     | Across 576,000 code samples from 16 LLMs, hallucinated packages averaged at least 5.2% for commercial models and 21.7% for open-source models (205,474 unique fake names), creating "slopsquatting" risk. | [Spracklen et al., USENIX Security 2025 (arXiv:2406.10279)](https://arxiv.org/abs/2406.10279)    |
| Project context pinning (Layer 2) | Dependency and environment conflicts stem from LLMs falling back to training-data averages rather than repo-specific versions and import paths.         | [LLM Hallucinations in Practical Code Generation (arXiv:2409.20550)](https://arxiv.org/pdf/2409.20550) |
| Escape hatch & brevity            | Tight constraints helped mid-tier `gpt-4o` (97% vs. 93% CoT) but degraded `gpt-5` (94.00% vs. 96.36% CoT) via hyper-literalism ("Guardrail-to-Handcuff" transition). | [The Prompting Inversion (arXiv:2510.22251)](https://arxiv.org/html/2510.22251v1)                |
| No persona / urgency fluff        | Across 22,140 HumanEval+ evaluations, stacking compound constraints (format + persona + urgency) caused super-additive `pass@1` drops of 3 to 12 percentage points (up to -12.2 pp on GPT-4o-mini). | [Compound Prompt Constraints in LLM Code Generation (arXiv:2609.03156)](https://arxiv.org/html/2609.03156v1) |
| Checklists + CLI gates (Layer 3)  | Requirement checklists improve alignment (REA-Coder), but code LMs cannot reliably self-refine faulty code through intrinsic self-inspection alone (CYCLE). | [REA-Coder (arXiv:2604.16198)](https://arxiv.org/html/2604.16198v1), [CYCLE (arXiv:2403.18746)](https://arxiv.org/html/2403.18746v1) |
| System/user separation + CI       | Separating system and user prompts aids reusability, but frontier LLMs still violate instruction hierarchies under conflict without external enforcement. | [The Failure of Instruction Hierarchies (arXiv:2502.15851)](https://arxiv.org/html/2502.15851v4) |
